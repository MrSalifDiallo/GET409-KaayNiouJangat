**Phase 4 : Le Lab Sprint Équipes & Déploiement des Infrastructures (19h15 - 20h45)**

**Objectif :** Rendre les étudiants acteurs de leur projet en configurant l'infrastructure de leur équipe étape par étape.

L'enseignant lance le chronomètre officiel de la séance.

**📦 ÉTAPE A : Alignement Humain (19h15 - 19h25)**

* Les étudiants se regroupent par équipes mixtes de 4 à 5 profils complémentaires (Business, Finance, Droit, Marketing).
* Ils choisissent un nom d'équipe court, mémorable et **sans caractères spéciaux** (ex: *TeamNiayes*, *InnovateDakar*).
* Ils distribuent obligatoirement les 4 rôles stratégiques : **Chef de Produit (PM)**, **Master Prompt Engineer**, **Dev UI (No-Code)**, et **Responsable Impact**.

**🛠️ ÉTAPE B : Création Pas à Pas du Dépôt GitHub d'Équipe (19h25 - 19h45)**

L'enseignant demande au **Dev UI** de chaque équipe de prendre le contrôle de son ordinateur pour exécuter la manipulation collective suivante au tableau :

1. **Initialisation :** Connectez-vous sur votre compte GitHub individuel, cliquez sur le bouton **"+"** en haut à droite, puis sélectionnez **"New repository"**.
2. **Nommage Strict (Nomenclature du cours) :** Dans la case *Repository name*, tapez obligatoirement GET409-[NomDeVotreEquipe] (Ex: GET409-TeamNiayes).
3. **Garantie de transparence :** Cochez impérativement la case **"Public"**. *(L'enseignant insiste : un dépôt laissé en "Private" ne pourra pas être lu par l'équipe pédagogique et vaudra un zéro automatique)*.
4. **Création du README :** Cochez absolument la case **"Add a README file"** pour initialiser la page d'accueil, puis cliquez tout en bas sur **"Create repository"**.
5. **Partage des accès (Droits d'écriture) :**

* Allez dans l'onglet ⚙️ **Settings** (Paramètres) en haut de votre nouveau dépôt.
* Dans le menu de gauche, sous la section *Access*, cliquez sur **"Collaborators"**.
* Cliquez sur le bouton vert **"Add people"**.
* Tapez l'adresse e-mail ou le username GitHub de chaque membre de votre équipe, attribuez-leur le rôle **"Write"** (Écriture) et validez.
* *Interactivité :* Chaque membre de l'équipe ouvre immédiatement sa boîte mail pour cliquer sur **"Accept invitation"**.

**🤖 ÉTAPE C : Configuration Pas à Pas de l'Espace Dify d'Équipe (19h45 - 20h00)**

Le Dev UI reste aux commandes pour lier l'équipe sur la plateforme d'IA en français :

1. Sur votre onglet **Dify.ai**, cliquez sur l'intitulé de votre espace par défaut en haut à gauche de l'écran (ex : *Dify's Workspace*).
2. Dans le menu déroulant, cliquez sur **"Créer un espace de travail"**.
3. Nommez cet espace collectif selon la nomenclature officielle : GET409-[NomDeVotreEquipe] (Ex: GET409-TeamNiayes).
4. Allez dans ⚙️ *Paramètres > Membres > Inviter des membres*, et saisissez les adresses e-mails de vos coéquipiers pour leur donner accès à la future interface de programmation No-Code.
5. **Mise en attente stricte :** L'enseignant donne la consigne de rester sur l'écran d'accueil du **Studio** et de ne cliquer ni sur *"Créer à partir de zéro"* ni sur *"Créer à partir d'un modèle"*, car cette manipulation de blocs fera l'objet exclusif de la Séance 3.

**📝 ÉTAPE D : Cadrage, Prompting & Écriture du README (20h00 - 20h45)**

1. **Cadrage Terrain :** L'équipe sélectionne un secteur au Sénégal (Souveraineté alimentaire, micro-finance verte, éducation).
2. **Exécution des Prompts Étudiants :** Le Master Prompt Engineer utilise le prompt **S1** (Découverte) sur ChatGPT et le prompt **S2** (Interview) sur Claude pour structurer un guide d'entretien. Deux membres simulent immédiatement une interview d'empathie en direct de 5 minutes.
3. **Génération des Livrables en Markdown :** L'équipe utilise le prompt **S3** (Générateur de HMW) pour définir leur problématique sous la forme d'un énoncé *"Comment pourrions-nous... ?"*. Ils terminent par le prompt expert **S4** pour compiler leur carte d'empathie finale au format Markdown strict.
4. **Mise à jour de la carte d'identité GitHub :** Le Dev UI copie l'URL de son dépôt GitHub depuis la barre d'adresse de son navigateur. L'équipe va sur son dépôt GitHub, clique sur l'icône du **petit crayon noir** sur le fichier README.md, y colle l'intégralité des textes générés (Tableau de l'équipe, Enoncé HMW et livrables Markdown), puis valide en cliquant sur le bouton vert **"Commit changes..."**.
